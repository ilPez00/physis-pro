Physis

An ontological engine that understands what an action is.

Physis turns any text, image, or signal into a position on a semiotic grid — a map of human activity — and then learns from feedback about which classifications were right. It is the engine behind the ontological features in Praxis, and it ships as a small, dependency-light core (physis-core) that larger systems build on.

What it actually does

1 · Embed

Every input becomes a vector. The default embedder is deterministic and model-free (so it runs anywhere with zero setup); a real ONNX MiniLM embedder can be swapped in behind the same trait when quality matters more than zero-dependency.

2 · Classify

The vector is scored against the ontology and placed in a cell of a 5 × 14 grid: the domain (the what) against the mode (the how). Classification is nearest-entry cosine, so a densely populated cell can't drown out a precise match.

3 · Cohere

Entries become coherence nodes — goals, notes, observations — that cluster, branch (certified vs. isolated), and surface contradictions. A dream loop tests assertions against the graph before they harden.

4 · Learn from feedback

When a classification is marked right or wrong, the cell is rewarded or penalized. Future rankings shift accordingly, so the engine improves from use without retraining.

The semiotic grid

A classification is a coordinate domain × mode. The vertical axis is the HEALCONSTRUCTFABRICATEBONDSTUDY and the horizontal axis is the manner of operation — LIFTRESTWALKWORKCREATELEARNDESTROYSENSEGUIDEPLAYBRAINSTORMMAINTAINMOVEPLAN. That is 70 base cells; ontology packs fill them with entries.

Beyond the grid: facets

The grid is a 2-D projection of a richer action space. To classify "whatever possible action" without bloating the grid, each entry also carries orthogonal facets: process lifecycle (Design/Build/Operate/Retire), agency (Self/Other/Automated/Collective), scale (Personal→Civil), abstraction, and tree-nesting (sub_domain / sub_mode). Facets are optional, so existing ontologies keep working, and classification can be filtered by them.

Ontology packs

The human grid is the base layer. Parallel packs — office (75 domains), machine (23 process domains), agent (21 AI-workflow domains) — share the same grid vocabulary with their own terms, and custom layers can be added on top. Expansion comes from adding packs and facets, not from rewriting the engine.

MCP Agent Connection

Connect agents with Physis via MCP protocol. This enables AI agents like Claude Desktop, Cursor, or any MCP-compatible client to perform ontology tasks:

  • Classify text with physis_classify
  • Query ontology with physis_ontology
  • Train quality models via feedback with physis_feedback
  • Discover entries from documents with physis_discover

Quick Setup

  1. Start server: ./physis-pro serve
  2. Configure agent: 127.0.0.1:9876
  3. Example call: { name: 'physis_classify', arguments: { text: "your text" } }

Claude Desktop / MCP client config

{
  "mcpServers": {
    "physis": {
      "command": "/path/to/physis-pro",
      "args": ["serve"],
      "env": { "PHYSIS_HOST": "127.0.0.1", "PHYSIS_PORT": "9876" }
    }
  }
}

Or point any SSE-capable MCP client at http://127.0.0.1:9876 after starting the server. Tools exposed: physis_classify, physis_ontology, physis_feedback, physis_discover.
