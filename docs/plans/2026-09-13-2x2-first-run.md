# The 2×2 ran for the first time — three defects first, then a floor

RESCOPE §6 item 3 ("build arms B, C, D of the §3 2×2") has been the top open
item since the re-scope. The harness was committed in `ded5819` and explicitly
not run. This is the record of running it.

Nothing here licenses a claim about the small-model thesis. Three arms of four
scored **0/7**, the fourth scored 1/7 on a case whose target file this session
had just edited, and the ceiling arm B is on the floor with the rest. A control
shows the gate is sound and the ceiling at full-file context is 5/7 — so the
zeros are a property of context assembly at a 3000-token budget, not of the
gate.

## Configuration

| | |
|---|---|
| Large tier | `nvidia/nemotron-3-ultra-550b-a55b` via NVIDIA NIM (`https://integrate.api.nvidia.com/v1`), free |
| Small tier | `qwen3:4b` via ollama on **omo** (16 cores, 8.5 GB ROCm) |
| Corpus | `physis-core/src`, 56 files, 771 candidate chunks |
| Budget | 3000 tokens, `--top-k 30`, `--diversity 0.3` (the CLI default) |
| Cases | the 7 of 10 in `cases.json` scoped under `physis-core/src`, all gated by `must_mention` |

opencode zen was tried first and refuses direct API use — `"OpenCode's free
tier can only be used in OpenCode"` (it wants a session id). The `GEMINI_API_KEY`
in `~/.env` returns `"Please pass a valid API key"`. `NVIDIA_API_KEY` works.

A 550B beside a 4B is a genuine tier gap. It is a free hosted endpoint, not a
frontier API, and should be labelled that way.

## Three defects, found by running the thing

### 1. The packer returned 4 of 3000 tokens at the default diversity

`TokenFixedRetriever::retrieve` accepted a candidate only if no higher-scoring
chunk beat it once discounted — and the scan that decided this included the
chunks it had **already selected**. A selected chunk is at cosine 1.0 with
itself, so it kept its full `base * (1 - diversity)` and out-scored nearly
everything below it for the rest of the run.

The CLI default is `--diversity 0.3`, so this is what shipped:

```
--diversity 0    packed 2938/3000 tokens from 19 chunks
--diversity 0.3  packed    4/3000 tokens from  2 chunks   ← two closing braces
```

Every packed context assembled through the default path was effectively empty,
and `summarize()` reported it as a successful pack. Fixed with a plain greedy
MMR in `physis-core` `a8da284`.

**The fix then did not reach the CLI**, because `src/pack.rs` uses
`crate::rag::TokenFixedRetriever` — physis-pro carries its own near-identical
copy of the retriever. Same bug, fixed again in `3db5afa`. That duplication is
the real finding and belongs to **PH-012 (core API stability)**: every
retrieval fix has to be made twice, and this one silently was not.

After both: 18 chunks, 2997/3000 tokens at the default diversity.

### 2. A flag believed inert crippled the oracle

`answer.py` sent `chat_template_kwargs: {enable_thinking: false}` to every
tier, on the measurement — correct, and recorded in the commit — that ollama
ignores it. **NVIDIA NIM does not ignore it.** On the same context and prompt:

```
with enable_thinking=false   1.2s   reasoning 0c      → "SHA-256"  → gate miss
without the flag             5.3s   reasoning 1798c   → "SHA256"   → gate pass
```

That is how arms A and B first came back 0/6 on contexts that demonstrably
contain the identifiers — a pack of the `artifact-integrity` case carries
`sha256` three times. Removed in `ffbcb28`.

Worth keeping in view: the gate is literal, so the *formatting* of a correct
answer decides it. `SHA-256` and `SHA256` are the same fact and score
differently. That is the price of a gate nobody can argue with, and it is
probably the right price, but it means a near-miss list is evidence and a
rate alone is not.

### 3. The packed arms ran on the wrong embedder, and nothing said so

`models/bge-base-en-v1.5/` held `config.json` and `tokenizer.json` but no
`model.onnx`, so `is_available()` was false and the cascade
(BGE → BGE-M3 → CLIP → MiniLM → random-projection) fell through to **MiniLM**.
RESCOPE puts BGE-base at +0.132 `support_2` over MiniLM, so both packed arms
were understated. `pack` prints `[physis] pack embedder: minilm` on stderr —
which `pack_context()` strips, so no result file recorded it.

The repo already knew it wanted the file: `models/bge-base-en-v1.5/.cache/`
carried a download record for `onnx/model.onnx` with sha256
`9bc579acdba21c25…` and no file beside it. Fetched it (436 MB, gitignored);
the checksum matches that record and the cascade's self-test now passes it:
`[physis] pack embedder: bge-base`.

`answer.py` now returns the embedder from `pack` and writes it into the
results as `pack_embedder`. A packed arm that does not say which embedder
packed it is not a measurement.

### One dropped case voided a whole arm

Both large arms lost the *same* case to `HTTP 503 Service Unavailable`, which
correctly voids the arm — a case that never reached the model is not a failed
case. Same case twice is load, not content, so transient statuses (429, 5xx)
are now retried four times with exponential backoff, and the retry is printed.
4xx is not retried: a bad request retried five times is still a bad request.

## The result

Canonical run: `pack_embedder: bge-base`, budget 3000, `physis-core/src`,
7 cases, 0 errors in any arm. `benchmarks/retrieval/answer-results-ABCD.json`.

|                  | naive context | physis-packed |
|------------------|---------------|---------------|
| **large** (550B) | B **0/7**     | A **1/7**     |
| **small** (4B)   | D **0/7**     | C **0/7**     |

```
A - B = +0.14   (packed beats naive on the large model, at equal context size)
C - D = +0.00
C - B = +0.00
```

**`A - B = +0.14` is one case out of seven.** By the standing rule of this
track — treat any positive as an artifact until a construction-matched control
says otherwise — it is an artifact. It is reported because it is what ran, not
because it supports anything.

And it has a named confound. The single passing case is `budget-packing`,
whose target file is `physis-core/src/rag.rs` — **the file this session
edited**. Defect 1's fix added about twenty lines of comment prose about
budgets, packing and token totals to precisely the file that case asks about,
which can only have raised its match to the query "how is the prompt kept from
overflowing the window no matter how large the corpus grows". The corpus was
modified during the measurement. A run that wants to claim `A - B` must pack
over a pinned revision.

The `C - B = +0.00` line printed by the harness reads "0 means the small model
matched the ceiling". Here it means both sat on the floor. That gloss is only
true when B is off the floor, and the harness does not check — see next steps.

### The near-miss gradient (post-hoc, not the gate)

Each case requires two identifiers, so 14 per arm. Counting identifiers *named*
rather than cases passed:

| arm | identifiers named |
|---|---|
| A packed/large | **4 / 14** |
| C packed/small | 2 / 14 |
| D naive/small  | 2 / 14 |
| B naive/large  | 1 / 14 |

This is descriptive and post-hoc. It was not the pre-registered gate, it has no
control, and it must not be quoted as a result. It is here because it points at
where to look: the ordering is the one the thesis predicts, at a sample size
that cannot support saying so.

### On the MiniLM run

The same 2×2 on MiniLM packs (kept at
`answer-results-ABCD-minilm-thinkingoff.json`, and with defect 2 still present
in arms A and B) scored **0/7 in every arm**. Swapping the embedder to the
documented primary is what moved arm A off the floor. That is one case, and
subject to the same confound, but it is the only lever tried so far that moved
anything.

## The control that makes the zero readable

A 2×2 in which the ceiling arm is also zero measures nothing: there is no
ceiling to reach, and `C - B = 0` would then be an artifact of the floor, not
support for the thesis. So the gate was put in front of its own null — the
same rule this track has earned seven times, applied to a negative instead of
a positive.

Hand the model the **exact file each case names**, whole, and score it the same
way:

```
cascade-selection        PASS
probe-discrimination     fail  missing=['cosine']
budget-packing           PASS
reference-model-absent   PASS
structure-recovery       fail  missing=['NEGATION_MARKERS']
sparse-counts            PASS
artifact-integrity       PASS

ORACLE CEILING (exact expected file as context): 5/7
```

The gate registers positives. It is answerable, it is not mis-specified, and
5/7 is what the *file* is worth to this model.

This control is **not budget-matched** — it hands over whole files (5.8k–39k
chars) against the arms' 3000-token budget. It says the gate works. It does
not say the arms are comparable to it.

So the zero is located: at a 3000-token budget over 56 files, neither the
physis-packed context nor the naive round-robin dump carries what the whole
file carries, for either tier. What separates 5/7 from 0/7 is context
assembly.

## What this does and does not license

- **Does not** support the small-model thesis. `C - B = 0` with both arms at
  the floor is not "the small model matched the ceiling"; it is two zeros.
- **Does not** refute it either. An instrument that reads 0 on both arms has
  not discriminated them.
- **Does not** license `A - B = +0.14`: one case, on the file this session
  edited.
- **Does** establish that the gate is sound and the ceiling is 5/7 at full-file
  context.
- **Does** establish that RESCOPE §6 item 3 is now **built and run**, and that
  running it is what found three defects that would have made any earlier
  number wrong.
- **Does** locate the next question, below.

## Next, ranked

1. **Find the budget at which the arms separate.** Sweep the budget (3000 →
   6000 → 12000 → whole-file) on arm B alone; the point where B leaves the
   floor is the first budget at which the 2×2 can say anything. Running the
   arms at a budget where nothing scores is spending a 550B to measure noise.
2. **The packer's top hits are degenerate.** At 3000 tokens the top four chunks
   are 1–2 token fragments (`}`, a closing brace) scoring 0.87–0.88. They cost
   6 tokens, so they are not why the arms fail, but a retriever whose best
   match for "how does the engine pick an embedding model" is a closing brace
   is reporting something about the chunker (`CHUNK_LINES = 40` windows split
   mid-item) or the embedding of very short strings. Worth its own packet.
3. **Re-run the 2×2 once (1) has a budget.** Not before.
4. **Pin the corpus.** Pack over a fixed revision of `physis-core/src` (a
   `git worktree` at a named commit), so a session that fixes a bug cannot
   move the thing it is measuring. This run could not separate "bge-base
   helped" from "I wrote the answer into the file".
5. **The `C - B` gloss lies when B is on the floor.** The harness prints "0
   means the small model matched the ceiling" without checking that there is a
   ceiling. It should refuse the line, or label it, when B is at 0.
6. **An empty answer is scored as a failure.** One arm-C case in the MiniLM run
   returned empty `content`. Same shape as the 503 rule already in the harness
   — a case that produced nothing is not a case that answered wrongly — and it
   is not handled.
7. **PH-012** owns the duplicated retriever (defect 1).
