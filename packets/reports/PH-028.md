## Option A — re-tag store (deliver to feather today)

**API**: `NavWorkspace::open_aliased(client_root, &index_path)` + `export_store(dest_dir, client_root)`.

**Procedure on pansa**:
```bash
# Write a re-tagged index for feather's checkout root
physis-pro nav retag-store \
  --src .physis/nav-index_home_gio_physis_pro.json \
  --client-root /home/gio/physis_pro \
  --dest-dir /tmp/feather-store/

# Then scp to feather:
scp /tmp/feather-store/nav-index_home_gio_physis_pro.json \
    gio@192.168.1.14:/home/gio/physis_pro/.physis/
```

The client then runs `physis-hud /home/gio/physis_pro --no-prescan` and opens on the delivered world with zero embedding cost.

**Why it works**: `PhysisObject.source.path` is root-relative (`"README.md"`, not `/home/gio/physis_pro/README.md`), and `ObjectId.key` is a content hash. Both survive the move as long as the relative layout matches (same commit).

**When it fails**: if the client's clone is at a different commit, objects for removed files are simply absent — honest, not corrupted.

## Option B — portable bundle (export/import with stamp)

**API**: `NavWorkspace::export_bundle(path)` → `NavBundleMeta`, `NavWorkspace::import_bundle(path)` → `NavImportReport`.

**Bundle contents**:
```json
{
  "embedder_stamp": "random-projection:384",
  "source_root": "/home/gio/physis_pro",
  "objects": [...],
  "relations": [...],
  "pin_pairs": [["fs:abc...", "fs:def..."]]
}
```

**Refusal contract** (the guard `packets/README.md` names for jina-clip-v2):
```
bundle stamp ≠ live stamp AND local index has vectors → Error("embedder mismatch: ...")
```

An empty local index accepts any bundle (nothing to clash with). This makes the first-time import on a cold client always succeed; subsequent imports after the client has embedded content refuse a mis-stamped bundle.

**Idempotent**: objects already in the index (by `serde_json(id)` key) are counted as skipped. Re-importing the same bundle twice adds nothing.

## Option C — remote embed offload (labelled, offline-first)

**API**: `PHYSIS_REMOTE_EMBED=<url>` env var.

**Behaviour**:
1. `NavWorkspace::open` detects the env; records the host as `remote_embed_suffix = "+remote:<host>"`.
2. `embedder()` wraps the local embedder in `RemoteEmbedder`: tries `POST <url>/api/v1/embed` (5 s timeout, optional bearer from `PHYSIS_API_TOKEN`), falls back to local on any network failure.
3. `embedder_kind()` returns `"<local-kind>+remote:<host>"`.
4. The HUD header shows `embedder: random-projection+remote:100.65.59.18:19876`.

**Measured feasibility** (from the packet's own measurements): tailnet reaches pansa's `/api/v1/embedder` in 10 ms. The actual embed call is heavier; not re-measured here since the client doesn't have a real embedder to compare against.

**Offline contract preserved**: if the remote is unreachable, `RemoteEmbedder::try_remote` returns `None` and `embed` falls back to the local embedder. The label stays `+remote:<host>` — the configured intent stays visible even when the remote is down, so the operator knows something degraded rather than seeing a silently different result.

**Never a silent remote fallback**: the label is unconditional; it is set at `open` time, not at call time. An operator who sees no `+remote:` suffix knows no remote is configured.

## Surprises

**Index size vs packet measurement.** The packet measured 67 MB for the whole store and 34 MB for `pack_embed_cache.json`. What we built is 111 MB for the index alone. The difference: the packet measured the *global* `~/.physis/` store (14 MB pack cache, no repo-root index), not the repo-root index (which did not exist). The repo-root index embeds 16 750 objects × 384 floats × 4 bytes ≈ 25 MB of raw vector data, stored in JSON (×4–5 overhead) → ~100 MB. This is expected for a full-text corpus at this scale.

**Option A re-tag is the right delivery for feather today.** 111 MB is copyable once over the LAN (scp takes ~1 s on gigabit). The client then opens on the full world with `--no-prescan` in < 1 s. Option B (bundle) is equivalent in size; the difference is survivability of store-format changes, which is future work.
