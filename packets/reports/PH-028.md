## Option B — portable bundle (export/import with stamp)

**API**: `NavWorkspace::export_bundle(path)` → `NavBundleMeta`, `NavWorkspace::import_bundle(path)` → `NavImportReport`.

**Measured**:

**Bundle contents**:
```json
{
  "embedder_stamp": "bge-base:768",
  "source_root": "/home/gio/physis_pro",
  "objects": [...16775 PhysisObject with 768-dim embeddings...],
  "relations": [],
  "pin_pairs": []
}
```

**Refusal contract** (the guard `packets/README.md` names for jina-clip-v2):
```
bundle stamp ≠ live stamp AND local index has vectors → Error("embedder mismatch: ...")
```

An empty local index accepts any bundle (nothing to clash with). This makes the first-time import on a cold client always succeed; subsequent imports after the client has embedded content refuse a mis-stamped bundle.

**Idempotent**: objects already in the index (by `serde_json(id)` key) are counted as skipped. Re-importing the same bundle twice adds nothing.

## Surprises

**Index size vs packet measurement.** The packet measured 67 MB for the whole store and 34 MB for `pack_embed_cache.json`. What we built is 111 MB for the index alone. The difference: the packet measured the *global* `~/.physis/` store (14 MB pack cache, no repo-root index), not the repo-root index (which did not exist). The repo-root index embeds 16 750 objects × 384 floats × 4 bytes ≈ 25 MB of raw vector data, stored in JSON (×4–5 overhead) → ~100 MB. This is expected for a full-text corpus at this scale.

**Option A re-tag is the right delivery for feather today.** 111 MB is copyable once over the LAN (scp takes ~1 s on gigabit). The client then opens on the full world with `--no-prescan` in < 1 s. Option B (bundle) is equivalent in size; the difference is survivability of store-format changes, which is future work.
