# PH-030 report — ResultState: collapse hits/rows/sel into one coherent struct

## What was done
- `ResultState { hits, rows, sel }` owns the triple in `src/bin/hud.rs`; `App`
  holds one `rs` field, written only via `set_results()` (= one
  `ResultState::new` assignment), `back()` (snapshot restore), `enter_dir`
  (new `with_rows` constructor), workspace-switch (`ResultState::default()`),
  and the canonical cursor paths (`set_sel`, `apply_hud_effect(s)`).
- `#[cfg(debug_assertions)]` invariant in `new`, plus the same check in
  `restore` (the only path where `sel` arrives from outside) — a header-row
  cursor fails loudly instead of rendering a highlight on a header.
- Mandatory tests added: `result_state_sel_invariant` (should-panic,
  debug-only), `back_round_trip_restores_focus` (hits/rows/sel + focused
  object round-trip through `enter`/`back`).

## Trimmed gate output
- `cargo test --features tui --bin physis-hud`: 47 passed, 0 failed
  (45 pre-existing + 2 new).
- `cargo clippy --all-targets -- -D warnings`: clean.

## Surprises
- `enter_dir` was a third write path building `rows` by hand outside
  `ResultState::new`; fixed with a `with_rows` constructor rather than a
  restructure, per the packet's Never list.
- The packet's invariant test as literally specified (panic out of `new`)
  is unreachable — `new` computes `sel` itself. The check that can actually
  fire lives in `restore`, so the test targets that path.

## Unknowns / follow-ups
- None for this packet. `selected: Vec<NavHit>` remains a parallel selection
  store behind the `sync_selected_from_focus_state` bridge (documented in
  code, out of scope here).
