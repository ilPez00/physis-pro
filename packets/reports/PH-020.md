# PH-020 — the direction metric was process state

**Executed** 2026-09-13, pansa. Branch `agent/PH-020` (stacked on
`agent/PH-019`), pushed. `status: review`.

## What was done

`worst_covered` read `PHYSIS_DIRECTION_METRIC` on every call. It now takes a
`RetentionMetric` argument, and `check` reads the escape once at its own
boundary.

The packet offered two fixes and named the parameter version as preferred; that
is what shipped. The test-only mutex was rejected for the reason the packet
gave — it leaves the global in place and breaks again the next time someone
adds a test that forgets the lock.

## What surprised me

**The first version of the fix was not enough, and the gate did not catch it —
reading the call graph did.** Threading the parameter through `worst_covered`
left `check` reading the environment, and six tests call `check`. A regression
test that set the variable to prove the explicit metric ignored it would have
reinstated the identical race in a narrower window, and it would have passed.

The fix for that is `RetentionMetric::from_env_value(Option<&str>)` — the
decision as a pure function of the value, so the escape is tested without
touching process state. **This module's tests now mutate no process state at
all**, which is the property worth having; "the tests pass" was available
without it.

Worth recording as a trap: the original comment was *correct about the hazard
and wrong about the remedy*. It said "the variable is process-global" and then
restored the value, which addresses the wrong half — it is the window, not the
final value, that does the damage.

## Unknowns discovered

1. **Are there other process-global reads on hot paths?** This one was found by
   accident. `grep -rn 'std::env::var' src/` would answer it cheaply, and any
   hit inside a per-call function is the same defect waiting.
2. **PH-015 and PH-018 are the same shape** — shared mutable state crossing
   test boundaries — and neither is root-caused yet. PH-018's duplicate anomaly
   is deterministic in isolation, so it is probably *not* this shape; PH-015's
   content-search flake probably is.
