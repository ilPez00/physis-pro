## What surprised me

- **The registries were already the world.** `list_objects` + the capability
  table answered every question the constraint needed (kinds, verbs, risk,
  cost, labels, state); the only gap was one accessor for object meta. Had I
  built an object model first, it would have been a second one.
- **`Access::ReadOnly` is the natural default and it costs nothing** — filtering
  verbs before compilation means the read-only language is simply smaller. The
  mutating verbs never appear, so "permission denied" is not a runtime state at
  all in this path.
- **Args had to come from the executors, not the verbs.** The registry reads
  exactly `limit`, `content`, `cmd` + `confirm`; anything else would have been a
  fabricated argument domain. `read`'s bounded `limit` is the only free field in
  a service-action language — the entropy accounting made that visible.
- **A "CPU temperature"-style bypass needs a single reachable object.** With
  file+passage pairs in the index (both carry the same path), the plausible
  intent matches two visible objects, so the model is asked. That is the honest
  behaviour (two candidates is a choice), and it means the bypass rate depends on
  the indexer's granularity — worth measuring, not assuming.
- The measured fixture run shows `2.58 bits` for a six-object world: small, but
  it is *derived* rather than asserted, and it falls to 0 bits when the language
  has one verb and one target.
