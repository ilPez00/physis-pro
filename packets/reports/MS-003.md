## Results

### Transform Subsystem
- **Total tests**: 8 (4 inline + 4 bench)
- **Production callers**: ZERO — only invoked from tests/examples
- **Acceptance gate**: Deterministic — composite ≥ `ACCEPT_FLOOR` (0.5) AND logical == 1.0 AND empirical == 1.0; only Logical and Empirical are hard-required (Temporal, Causal, Procedural are scored, Semantic stays neutral)
- **Predicate enum**: 8 variants + Custom(String); invert mapping is Exchanges→Exchanges, Causes→Causes, Requires↔Produces (Causes is self-inverse)

### Becoming Subsystem
- **Total tests**: 12 inline
- **Production caller**: Single — `chain.rs:418-442` on `map.repeats` (max 8 families), requires ≥6 `Occurrence`s
- **Algorithm**: `two_means` (cosine similarity on document embeddings, separation threshold 0.15) + `runs_z` (Wald-Wolfowitz runs test, threshold -1.96)
- **Input**: Document-level embeddings ordered by document index (not per-token, not fine-grained position)

### Relation Subsystem
- **RelationType variants**: 15 — structurally orthogonal to both Transform and Becoming
- **TypedEdge**: Carries `RelationType` but no measurement pipeline connects to `Transform::apply()` or `becoming::classify()`
- **Predicate vs RelationType**: 8 vs 15 variants, different enums, no conversion trait, conceptual overlap (Causes, Produces, Requires, Supports, Contradicts, Precedes, Observes appear in both) but not unified

### PH-051 Context
- 4/5 candidates transfer across representations, but 0/5 are arithmetic-specific and 0/5 survive held-out representations (`packets/reports/PH-051.md` §Result): transfer without specificity — exactly what a successor must not mistake for a failed transfer
- Becoming uses cosine similarity (geometry-dependent, representation-sensitive) but `runs_z` is a counting statistic (potentially more representation-invariant)

---

## Limitations

1. **No relation measurement infrastructure** — `Transform` (Predicate) and `RelationType` are separate enums with no mapping, conversion, or shared measurement pipeline
2. **Becoming uses document-level embeddings** — not per-token; ordered by document index, not fine-grained position; `two_means` depends on cosine geometry
3. **Benchmarks are behavioral agent benchmarks** (`physis-core/tests/*.rs` = epistemic, temporal, delta engine) — not linguistic-semantic relation survival measurements
4. **No dedicated relation test file** in `physis-core/tests/` — only `transform_bench.rs` exists for transform
5. **PH-051 established** transfer without specificity (4/5 transfer, 0/5 arithmetic-specific, 0/5 held-out-surviving) — `runs_z` may be more invariant but unproven
6. **Ground-truth corpus absent** — no renamed/paraphrased document pairs exist in repo for relation survival holdout testing

---

## Decision

**MS-003 is research-only, report-only. No production edits authorized.**

### Structural Findings (not defects)
- Transform–Relation gap: separate enums (Predicate 8, RelationType 15), no mapping
- Becoming invoked only from `chain.rs` on repeat families (max 8, min 6 occurrences)
- Acceptance is deterministic gating (composite ≥ 0.5 with Logical and Empirical hard-required; Temporal/Causal/Procedural scored, Semantic neutral)

### Recommended Follow-up
1. **Create synthetic ground-truth corpus** — small set of renamed/paraphrased document pairs with known relation survival labels, frozen before holdout inspection
2. **Design relation survival metric** — must bridge Predicate ↔ RelationType, survive representation change (embedding model swap, tokenization change)
3. **Evaluate `runs_z` invariance** — test Wald-Wolfowitz statistic under embedding model changes (PH-051 suggests counting statistics may transfer better than cosine geometry)

### Amendment A1 Compliance
All collection comparisons in this report use sorted sets; float thresholds reported to ε=1e-6 precision (0.500000, 0.150000, -1.960000).

### Corrections required

1. **The acceptance gate is described wrongly (high).** The report says
   "5 binary gates in `Transform::apply` — Logical, Empirical, Counterfactual,
   Substitution, Analogical — all must be 1.0 + composite ≥ 0.5". The gate
   (`transform.rs:633-639`) sets **logical, empirical, temporal, causal,
   procedural** and accepts on
   `gates.composite() >= ACCEPT_FLOOR && logical == 1.0 && empirical == 1.0`.
   Only **two** dimensions are hard-required; `Counterfactual`, `Substitution`
   and `Analogical` are test names, not gates. `CoherenceProfile`
   (`coherence_dimensions.rs:52-59`) has six fields — semantic, logical,
   temporal, causal, procedural, empirical — and `apply` leaves `semantic`
   neutral.
2. **The `invert()` mapping is wrong (medium).** The report lists
   "Causes↔Produces". `Predicate::invert` (`transform.rs:52-60`) is
   `Exchanges→Exchanges`, `Causes→Causes`, `Requires↔Produces`. `Causes` is
   self-inverse.
3. **PH-051 is misquoted (high).** The report says "0/5 candidate probability
   laws cleared cross-representation transfer". PH-051's own record
   (`packets/reports/PH-051.md` §Result) is **4/5 transfer**, 0/5
   arithmetic-specific, 0/5 held-out-surviving. The distinction is the whole
   point of PH-051: transfer without specificity is exactly what a successor
   must not mistake for a failed transfer.
4. **Two line citations drift (low).** `src/transform.rs` is **750** lines, not
   759; `mod tests` starts at **653**, not 652. Command 6 in the report
   (`grep -rn "becoming::" src/` from the repo root) returns nothing as written
   — the hits it quotes are `physis-core/src/chain.rs:421-434`. The described
   integration is correct: `map.repeats.iter().take(8)`, `occs.len() < 6`
   continue, `becoming::classify`.
