# PH-024 report — physis-hud is the one front door

Branch: `agent/PH-024` (from `3b29780`). Box: pansa. Date: 2026-09-20.

## What was done

1. **`config::CONFIG_KNOBS`** (`src/config.rs`) — one table for the five runtime
   knobs: key, decimals, floor, ceiling, step, getter, setter, plus
   `value`/`set`/`bump`/`display`. `src/bin/tui.rs` and `src/bin/studio.rs` now
   delegate (`edit_field`/`cfg_value` became thin wrappers; Studio's unused
   `cfg_value` was deleted). Three private copies of the same five knobs are
   gone, so a panel can no longer disagree with the CLI about what "the config"
   is, how far a step moves, or where a knob floors.
2. **Views** (`src/bin/hud.rs`) — `View::{World,Graph,Notebook,Tasks,Agents,Settings,Setup,Help}`
   with `ALL`, `label`, `key`, `from_name`, `from_key`, `next`, `prev`, `keys`.
   Every surface that used to be written into the 35 %-high reading pane (task
   graph, agents, settings dump, notebook answer, graph, help) is now a named
   view that owns the main pane; the world stays underneath and `Esc` returns.
   Keys: `Tab`/`BackTab` cycle, `g N T A S W ?` open, plus the existing
   commands (`:settings`, `tasks`, `agents`, `setup`, `world`). `View::from_key`
   drives one catch-all arm, so a future view key needs no new match arm.
3. **Editable SETTINGS view** — `SettingRow::{Section,Knob,Provider,CommandEnabled,CommandAliases}`,
   `ProviderField::{Transport,Bin,Model,KeyEnv,Endpoint}` (+ `hint`),
   `settings_rows` (deterministic: knobs → providers → commands), `setting_value`
   (unset prints `-`; `key_env` prints the env var **name**), `step_setting`
   (knobs clamp through the shared table, `transport` cycles a closed set
   `zen·cli·http·local`, command rows toggle, text rows return `Ok(None)`),
   `set_setting_text` (validates through `Settings::set` on a scratch document,
   with one exception arm for knob keys), `next_setting_row` (skips headers,
   wraps), `row_hint`. The App keeps `settings` (always defaults + user file +
   session changes), `cfg`, `settings_dirty`, `config_dirty`, and only dirty
   keys are written on save — a save cannot freeze today's shipped defaults into
   the user's file, which is what `Settings::save` on the merged document would
   have done.

4. **SETUP view + `--setup`** — `SetupFacts` (root, index counts, tokens,
   embedder, semantic, paths, settings presence, roster reachability) and pure
   `setup_report`: WORKSPACE / FILES / AGENTS / CHECKLIST / NEXT, each gap naming
   the command that closes it. `physis-hud --setup` prints it without a prescan
   and exits 0. `--view <name>` opens a view directly; an unknown name exits 1
   and lists the valid ones, so `--snapshot=100x30 --view settings` is a
   CI-renderable frame.
5. Plan: `docs/plans/2026-09-20-physis-hud.md` (reuse map, gaps, phases P0–P7,
   rules per packet) — the programme this packet is step 0 of.
6. CHANGELOG `[Unreleased] / Added` records all of the above with PH-024.

## What surprised me

- **The shipped settings file already names the JEV env var**
  (`providers.jev.key_env = JEV_API_KEY`) and uses a transport (`local`) the
  HUD did not know. Both facts came out of tests failing, not out of reading the
  file first — the transport cycle now includes `local`, and the secret test
  asserts "prints the env name", not "prints `-`".
- **`Settings::get` does not return the normalised alias list.** Recording what
  the operator typed and letting the view re-render from the merged document is
  simpler and honest; the file still gets `a,b`, because `Settings::set`
  normalises on write.
- **`--snapshot --view settings` costs ~12 s** on this checkout, all of it the
  pre-existing `workspace_tokens` walk inside `App::new` (47.5 M tokens of
  tree). Snapshot mode is not the place to fix it, but a per-lens snapshot
  matrix in CI will multiply that cost — PH-025 should make the token walk lazy
  or cached.
- **`run_hud_command` returns `bool`,** so key arms that call it need a block;
  a sed pass produced `;;` and an unreachable `q` arm. Worth remembering when
  PH-025 moves keys into a table.
