# PH-002 — install.sh is broken as written — fix or delete

**Status: done.** Executed 2026-09-12 on the `agent/PH-001` branch. Decision:
**fix** (default per packet), mirroring the installer that `scripts/package.sh`
already ships.

## What was delivered

1. **`install.sh` rewritten** (root, developer-facing front door):
   - Now consumes the workspace's own `target/release` output and installs the
     real product binaries (`physis-pro`, `physis-pro-web`, `physis-pro-tui`,
     `physis-pro-wiki`) to `$PREFIX/bin` (default `~/.local/bin`) and
     `config/*.json` to `~/.physis/config`.
   - No `sudo`, no system paths, idempotent (`mkdir -p` + `cp -f`), and only
     touches `PREFIX/bin` and `~/.physis/config` (its own dirs).
   - `--dry-run` prints the plan and changes nothing (exit 0); `--help`/-h too.
   - Dropped the bogus `gateway/physis_mcp_gateway.py` wrapper — the binaries
     are the entrypoints.
2. **`scripts/tests/install-test.sh`** — the gate test: dry-run is a no-op in a
   temp HOME, names `physis-pro-web`, never references the old bogus name.
3. **Docs cleaned**: stale references to the old binary path removed from
   `PLAN.md` (H8 marked RESOLVED by PH-002) and `physis_bible.md` (3 copies).

## What surprised me

- `scripts/package.sh` already ships a *correct* embedded installer; the root
  `install.sh` was a divergent, hand-written copy that had rotted. Fixing the
  root one to match `package.sh`'s semantics cost little and removes a trap.
- The stale string also lived in 3 spots of `physis_bible.md` (a rolled-up copy
  of the plan) — the gate's `.md` sweep caught those, so they had to be cleaned.
