### 1. The chain that was tested and never called

`hud::intent::compile_bare` was reachable only from its own tests — the defect
shape `docs/WHAT_PHYSIS_IS.md` §7 names. `submit_command_line` now resolves bare
text through `resolve_bare` and the **status line carries the route**:

```text
route=exact-object object=fs:<full-hash>
route=intent-ir objects=4 nil=[constraints,context,required_state,…]
```

"Exact" is exact: the world's own exact-path rule (`NavWorkspace::resolve_exact`,
new; file over passage, no trail side effect) decides `exact-object`, and
everything weaker — label match, prefix match, a ranked hit — stays `intent-ir`.
The IR is reachable from `:intent` rather than merely stored. The wiring is
gated by a bin test that **fails when the call is removed** (verified by
removing it).

### 2. Five routes with no producer, deleted

`ResolutionRoute` shipped seven variants; only `ExactObject` and `Intent` are
produced anywhere in the crate. An enum of routes is an executable description
of reality, not a roadmap, so `Parsed`, `ExactFact`, `Guided`,
`AgentEscalation` and `Human` are gone. The deferred legs are named in the
module header — prose, not types, until each has a caller. `ExactFact` is
deliberately **not** built to make the enum symmetrical: the prototype
`sensors.rs`/`fact.rs` machinery needs a caller, a test and a genuinely useful
structured query first.

### 3. The second lens, and the commonality it justified

`RowRelation`, `ProjectionRow`, `ProjectionGroup`, `Projection` are the shape
both lenses actually share — extracted **after** the second lens existed, as the
packet required. `SemanticLens` projects the same ranked list (never a second
ranking) into:

```text
categories: bridge 3 · strong 2          ← measured on feather
  - - [<bridge> 0.44 near] other.rs
  - - [<strong> 0.93 near] retrieval.rs
```

* `strong` — at or above a named threshold;
* `bridge` — a **two-hop** claim: close to the centre *and* to a strong
  neighbour, computed by cosine over persisted vectors (`bridges()`, pure and
  tested with hand-made vectors rather than whatever an embedder produces);
* `sibling` — shares the centre's directory (structure, not similarity).

Every similarity row is `Inferred` **by construction**: `ProjectionRow::near` is
the only neighbour constructor, so no renderer can present one as recorded.
Vectors of different lengths compare as unrelated instead of panicking — a
swapped model must not take a projection down.

### 4. The lexical lie, fixed at the source

PH-026 fixed the header; the internal vocabulary still called a hash "semantic".
Now the **component is named for the computation**: `vector`, not `semantic`
(`NavWeights.semantic` → `vector`, `explain_hit`, the attention readout, the
pane title, `tests/score_normalization.rs`). A frame from the client that has no

and the mode rule is stricter: semantic retrieval is in play only when the
embedder is not a lexical stand-in **and** the vector leg carries weight **and**
a vector component actually contributed.

### 6. Descend, and ask what may be done to the focused object

Two mission items that were still reachable after the first four commits:

* **Enter descends when there is something inside.** It used to always read the
  object and re-query its neighbourhood, which conflated *reading* with
  *descending*. Now a file opens onto its **passages in reading order** and a
  directory onto its **own entries** (`children_of`, read from the index, so it
  costs nothing and cannot fail on a permission bit); focus stays on the
  container so `WHY`/`:actions` still answer for the thing you opened; `Esc`
  restores the identity you left. Leaves keep the old behaviour.
* **`:actions`** wires `hud::palette::affordances_for_identity` into the running
  HUD. The seam existed with tests and **no caller** — the same defect this
  packet deleted five route variants for — so focus now answers "what may I do to
  *this* object?" from the registry the executor uses, and an object with nothing
  registered says so instead of showing a generic menu.

Both are gated by tests that fail when the behaviour is removed (the descend
branch was reverted to confirm). The §21 loop is now covered end to end:
focus → `:actions` → `:action read <handle> limit=2` → the observation is in
`registry_observations.jsonl`; the world-change half (edit → rescan → Δ markers)
is the pre-existing `inline_edit_save_rescans_records_delta_and_markers`.

**Writing that test hit §10's hazard for real.** Hand-assigning `hits`/`sel` left
`rows` stale, so `current_hit()` — which reads `rows[sel]` — returned a different
object and the descent looked broken. The fix was to mutate through the one path
(`set_results`), which is exactly the criterion PH-029 carries.

## What I did NOT do (and why it is written down)

* **No lens trait, no `LensRegistry`.** Two lenses share the *data* shape
  (`Projection`), which is the commonality that exists; a trait would have
  roughly one implementation and a "registry" of two functions is a `match`. It
  earns its place when a lens arrives that cannot be expressed as data.
* **Reducer ownership moved only for what existed** (`AgentReply`,
  `ProjectionChanged`, `SourceDiff`). Navigation mutations still write `App`
  fields directly; `MoveCursor`/`Select`/`FocusObject`/`Descend`/`Ascend` are
  the next packet's work, because moving them with no second consumer repeats
  the framework-before-need mistake.
* **Structural extraction (§12) untouched.** `extract_structural_lines` still
  matches unqualified `^fn`/`^struct`, so most `pub` items in this repo do not
  project as symbols — measured in PH-026 and still true. It starts blocking the
  acceptance loop when the project/content lenses land, not before.
* **Fleet half (§13) untouched** by instruction.

## Surprises worth keeping

* **The identity rule and the exact rule disagree about paths.** A path names a
  file *and* its passage, so hand-rolled "the line equals the object's label"
  found two matches where the world's own resolver finds one. The fix was to use
  the world's rule (`resolve_exact`, file over passage) rather than to special
  case the textbox — one rule, in one place.
* **A zero weight is not an absent leg.** The scorer keeps the raw component and
  applies the weight to the total, so `--no-semantic` shows the leg at weight
  0.00 rather than hiding it. Better for a readout, and now pinned by a test.
* **My own tooling bugs cost more than the code.** Two `python3 -c` invocations
  ate backticks out of doc comments (shell command substitution), and one editor
  insert replaced a `#[derive]` block instead of inserting before it. Both
  surfaced through the compiler and a regenerated module map, not through review
  — which is the argument for keeping the mechanical gates cheap.
