# PH-008 — Embedder registry image slot (closed)

- status: done

- worker: pansa (opencode) on branch `omo-008` → pushed to `agent/omo-research`.

## What was wrong

- The web server never used `EmbedderRegistry`: `SharedCtx` held a single
  text `embedder`, and `embed_input` called `embed_image()` on it — with
  bge-base active every image request silently fell back to text ("falling
  back to text" warn, client none the wiser).
- `EmbeddersConfig.image` (dedicated image-only embedder) existed in config
  but the registry never read it.

## Fix

- `VectorEmbed::handles_images()` (default false; true for Clip/Jina) —
  capability probe so callers report honestly instead of try-and-fallback.
- `EmbedderRegistry`: new `image_kind` field + `BuiltEmbedders` alias;
  `config.image` now fills an empty image slot (`build_image_only`, vision
  kinds only — never downloads, `is_available()` is a local-sessions check).
- `SharedCtx`: `image_embedder` + `image_embedder_kind` + `image_capable`
  (slot OR text's own capability — mirrors `embed_input` order; jina-as-text
  keeps working). Text embedder untouched.
- `embed_input` → `Result`: image resolves slot-first, text-fallback second;
  neither → **503 + `image embedding unavailable: image slot is '<kind>'…`**.
  Base64-decode failure keeps the old text fallback (bad input, not an
  incapable embedder).
- `classify_handler` / `embed_handler` → `Result<Json, 503>`; text-only
  callers (`register_node`, `match_route`) use `unwrap_or_default` with an
  unreachability comment.
- `/health` gains `image_embedder: {kind, degraded}`.

## Tests

- Unit (`embed::registry::tests`, 2): RP config → slot empty, kind None,
  `handles_images` false; `image: BgeBase` (text-only kind) → slot empty.
- Integration (`image_endpoints_503_without_vision_model_but_text_works`):
  POST /embed + /classify with 1x1 PNG under RP → 503 + reason naming the
  `none` slot; text embed/classify still 200; /health
  `image_embedder={kind:none, degraded:true}`.
