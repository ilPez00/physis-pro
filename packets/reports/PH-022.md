# PH-022 — `number_clash` was dead

**Executed** 2026-09-13, pansa. Branch `agent/PH-022` (`d468594`), pushed.

## What surprised me

**It was found by trying to beat it, not by auditing it.** The NLI experiment
needed the incumbent rule as a baseline arm — "beat cosine" is not the bar,
"beat what physis ships" is — which meant replicating `leading_number` and
`decimal_number` in Python. The replication disagreed with expectation, and the
Rust test then failed the same way: `left: None, right: Some("2.6")`.

Nothing in a normal audit would have caught it. The symbol is called, the branch
compiles, `physis-check sweep` sees a live call site, and the tests passed
because none asserted on it. It is a *dead condition*, not dead code — a
category the crate's own "declared ≠ called" check cannot see.

## Result

Fixed and gated: `map::` 3 passed, full `--lib` **271 passed ×2**, clippy
`--lib --tests` clean apart from two pre-existing `notebook.rs` errors.

And then measured, which is the part worth keeping: **it changes nothing on the
ground-truth corpus.** Incumbent precision/recall is 1.000/0.50 both before and
after, because the only pair with a measurement clash was already being caught
by negation asymmetry. A real defect repaired, with no benefit this corpus can
demonstrate.

Gate outcome: test portions pass (map:: 3/3, --lib 325/325), but clippy has 2
pre-existing errors in notebook.rs (useless vec!) unrelated to this fix. The
decimal_number fix is correct — it now returns `Some("2.6")` for
`"valve shall open at 2.6 bar"` and stays `None` for `"Release 17 deployed"`.

### The fix, read in the source (not inferred from the tests)

`src/map.rs:120-140`: `leading_number` now takes a digit-or-dot run
(`take_while(|c| c.is_ascii_digit() || *c == '.')`) and trims a trailing `'.'`,
where it previously took alphanumerics and stopped at the decimal point. The
comment above it records the failure that motivated the change
("used to stop at it, so \"2.6\" came back as \"2\" … left the `number_clash`
leg permanently `false`") — step 3 satisfied, and the motivating failure is
preserved rather than deleted.

The rule is live at the call site (`src/map.rs:349-354`):
`let (la, lb) = (decimal_number(ba), decimal_number(bb)); let number_clash =
matches!((la, lb), (Some(x), Some(y)) if x != y);` — now reachable with both
legs populated, which is what "dead branch" meant before.

Test `map::tests::decimal_number_actually_finds_a_decimal`
(`src/map.rs:546`) pins **both** halves as the packet demanded:
`Some("2.6")` for a measurement, `None` for `"Release 17 deployed"`, `None` for
no numbers. Verified to be the asserted behaviour, not just a passing test.

### Honest-result clause upheld

The report's §Result records precision/recall 1.000/0.50 **before and after**
the fix, i.e. a real defect repaired with no measured benefit on the current
corpus, and names why (no pair in the corpus is caught by a measurement clash
alone). That is the behaviour the development directive asks for. The finding
is not softened, so nothing here needs correcting.

### One finding for a future packet (not a blocker, not this packet's scope)

`src/map.rs:535-543`: the test's doc comment still describes the bug in the
**present tense** — "`leading_number` **ends with**
`.take_while(|c| c.is_alphanumeric())`, which stops at the `.'` — which is no
longer true of the code beneath it. The `leading_number` comment was updated
correctly; this one was not. The repo rule is about comments describing the
code they sit next to, so past tense ("ended with") is the fix. Left
unmodified: a reviewer pass does not edit source, and it changes no behaviour.
Worth one line in the next docs-staleness sweep (PH-011).

Verdict: **done**.

## Unknowns discovered

1. **Dead conditions are invisible to the existing checks.** `physis-check`
   answers "is this symbol called?" — not "can this branch ever be true?".
   Worth a `claims`-style verb, or a mutation-testing pass on the boolean legs
   of decision rules.
2. **The corpus cannot exercise its own rule.** The ground truth has no pair
   that a measurement clash alone would catch, so one third of the contradiction
   rule is untested by construction. That is a corpus gap, and it is cheap to
   close: two documents differing only in a decimal.
