### 2. One identity, three kind vocabularies, no fourth object model

`WorldObject.identity` is the `origin:key` spelling of `nav::ObjectId`;
`parse_object_id` parses it back (`view_identities_parse_back_to_canonical_nav_ids`).
The three kind enums stay separate **by scope** — nav (index storage), view
(includes agent/machine/service plus `Other(String)`), registry (strings) —
with one mapping per crossing (`lens_object::kind_of`). The new axis is
`Relation.origin`: view edges now say *how they are known*, so a directory scan
renders as a recorded fact and a similarity row never borrows that grammar.

### 3. The invariant the mission asked for, in one function

`FocusState::switch_projection` changes the projection and resets **only** the
cursor. Focus, explicit selection and trail survive. The bin's `open_view`
calls it via `bridge::switch_to`, so every shipped key (`g`, `N`, `T`, `A`,
`S`, `W`, `?`, `Tab`) inherits it, and the bin test drives it through
`App::open_view`, not the library alone.

### 4. Capability-derived palette, not a second menu

`hud::palette::palette_for` renders rows from `guided::WorldView`, which
derives from `Registry`: unknown target → no rows (never a guessed menu),
`high` risk → `needs_confirm()`. Three tests, one walking every object in the
seeded world.


### 5. A reducer with no executable branch

Agent replies used to be formatted inside the run loop, which meant the wording
of a model's failure and the shape of its success were untested strings built at
the call site. They now go through `hud::event`: the loop builds
`HudEvent::AgentReply`, `reduce` decides, `App::apply_hud_effect` applies.
`HudEffect` is `Status | Reading | ClearPending` — there is no variant that runs
anything, so the mission's "no model output acquires shell authority" is a
property of the type, asserted in both the library and the bin.

### 6. One name table, and the flake that came out of it

`View::label` and `ProjectionId::name` were two lists of the same eight strings
kept in step by a test. `View` now derives its label from `ProjectionId` and
parses names through `ProjectionId::from_name`, so a rename is a compile error;
the test that remains guards the part a compiler cannot see (the *order* of the
two tables, and the round trip).

Moving names into the library left three tests pointing the process-global
`PHYSIS_DATA_DIR` at their own stores and running in parallel threads: the suite
failed once and passed on re-run — a schedule-dependent flake, not a slow
machine. Fixed **twice over**, because there are two distinct races:

1. **In-process**: parallel test threads in one binary — fixed with a test-only
   `Mutex` plus the file's existing `RestoreEnv` guard.
2. **Cross-process**: cargo runs the lib and bin test binaries as separate
   processes, and a fixed `/tmp` path lets them collide even with the lock held —
   fixed by using `tempfile::tempdir()` for every test I added. A per-process
   lock cannot serialise two processes, so the lock alone would have been a
   partial fix reported as a complete one.

Verified by running the bin suite five times consecutively (40 passed, five
times). The vacuous `if others.is_empty() { return }` preconditions in two of
those tests became assertions for the same reason.

### Two defects this delivery exposed

1. **The client was told it had semantic retrieval.** `update()` hardcoded
   `semantic: true` and `RetrievalMode` asked whether a `semantic` score
   component existed — which the lexical hash produces too. On feather the
   summary therefore read `semantic: true (embedder: random-projection)` and the
   header `[semantic+lexical]`. Fixed with one predicate
   (`nav::is_semantic_kind`), now `semantic: false` / `[LEXICAL ONLY]`
   (commit `a1f5ece`; the forced-lexical test fails against the old code).
2. **The crate did not build without `embed-onnx`.** The import was gated, its
   use was not (`E0433`), so a lean client build was impossible and every client
   binary had to carry the onnx runtime it cannot use. Fixed (commit `07a6e4f`).

## What surprised me

- **The client was being lied to, and only the client could show it.** pansa
  picks `ollama-embed`/`bge-base`, so `semantic: true` was *accidentally*
  correct here for months; on the machine that has no embedding model the same
  line is false. The defect was in a code path that is exercised on every run
  and wrong only where it is hardest to notice.


- **The prompt's divergence claim was stale in the safe direction.** 138 ahead
  / 0 behind, not 142/6. A plan written from that claim would have spent its
  budget merging nothing, while the real prior art (`local-main-import`) was
  invisible from `main`.
- **The scanner vocabulary is weaker than the prototype assumed.**
  `extract_structural_lines` matches `^fn`/`^struct`, so `pub fn`/`pub struct`
  — most of this repo — do not project as symbols. The prototype test asserted
  `struct WorldObject` was found; mine discovered the same gap and pins it as a
  known scope rather than weakening the assertion silently.
- **The snapshot path needed a focus to be meaningful.** `App::new(root,false)`
  plus `--view graph` produced an empty pane, and `--view` for
  graph/tasks/agents/help never ran the command that builds their body. Two
  small additions (`--query`, command-backed `--view`) turned a decorative
  frame matrix into a real slice check.
- **clippy caught a misplaced test module** (`items_after_test_module`) after
  the tests were green. The test gate alone would not have.

## Unknowns fed back

- **Lens registry, not lens enum.** `ProjectionId` is still a closed 8-variant
  enum. The nine-lens programme wants lenses registered by id; this packet
  deliberately did not pre-build the trait.
- **The bin still owns rows/hits/selection.** `focus_state` is a mirror. Making
  the reducer own state, with `draw()` reading only from it, is the second half
  of P0 and needs the key arms moved behind `HudEvent`.
- **`--query` is a snapshot affordance, not the resolution chain.** The
  bare-text chain (`hud::intent`) exists and is tested but is not wired into
  `submit_command_line`; wiring it changes `HudInput` parsing, which has its
  own ten-test table.
- **Labelled degradation is interactive-only.** Semantic off is reachable
  through the in-app `sem off` command; there is no flag, so the mission's
  "lexical degradation is visible" invariant cannot be checked in a headless
  frame yet. A `--no-semantic` flag (one line through `--query`'s path) is the
  smallest change that makes it snapshot-testable.
- **Indexer granularity still decides focus.** `retrieval.rs:1-1` (passage) and
  `retrieval.rs` (file) are two objects with one path, so a projection-equality
  test must compare ids, not paths — the same trap PH-025 flagged for bypass
  rate.
